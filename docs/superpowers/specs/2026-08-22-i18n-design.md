# i18n Design — Language Toggle via Google Translate (Phase 1) + Swedish Overlays (Phase 2)

**Date:** 2026-08-22
**Status:** Approved design, pending implementation plan
**Scope decision:** Hybrid — ship a styled Google Translate integration now for instant broad coverage; defer quality-first Swedish overlays to a future phase.

---

## Decisions (user-approved)

| Question | Decision |
|---|---|
| Scope | UI chrome + full lore eventually; Phase 1 = whole-page MT via Google Translate |
| Languages | ~45 languages spoken across the archive's 212 countries |
| URL strategy | None in Phase 1 (`googtrans` cookie only). `?lang=` param reserved for Phase 2 |
| Translation engine | Google Translate Element (deprecated but functional), driven programmatically |
| Switcher | Square button below the theme toggle, identical size/style tokens; opens custom menu |
| Persistence | Google's `googtrans` cookie (restores across pages automatically) |
| SEO | Deferred to Phase 2 (hreflang + localized meta need real localized content, not client-side MT) |
| Fallback | If GT fails or is killed: button hides itself, site remains fully functional English |

## Phase 1 — Google Translate Integration

### Architecture

- **`js/language-toggle.js`** (new module):
  - Renders the square toggle button into `#site-nav` actions area, directly below the theme-toggle button, using the same class hooks and CSS custom properties as `.theme-toggle` so dimensions/hover/focus states match exactly.
  - On first click: lazily injects `<script src="https://translate.google.com/translate_a/element.js?cb=...">`, initializes `google.translate.TranslateElement({ pageLanguage: 'en', includedLanguages: <same codes as our menu>, autoDisplay: false, layout: google.translate.TranslateElement.InlineLayout.SIMPLE }, hidden container)`.
  - All Google-injected UI is hidden via scoped CSS (`.skiptranslate`, `.goog-te-banner-frame`, `.goog-te-gadget` etc. — same technique as the Ko-fi widget overrides).
  - Selecting a language from **our own menu**: sets the `googtrans` cookie (`/en/<code>`), then programmatically triggers the hidden combo (`select.value = code` + `change` event) to start translation. "Original" clears the cookie and restores.
- **Language map:** static object in the JS module grouping codes by region label (Nordic, Celtic, Western/Eastern Europe, Middle East, Asia, Africa, Americas), derived from the countries present in the archive. No backend.
- **Menu UI:** small dark-panel popover anchored under the button, styled with existing tokens (`--bg-card`, `--border`, `--accent`). Closes on outside click / Escape; focus-trapped per existing overlay pattern.

### Error handling

- Script load failure or missing `google.translate` namespace → button removes itself silently; console warn only.
- Menu disabled while a translation pass is running; re-enabled after. *(Mooted at implementation: menu closes on selection; re-open rebuilds from current cookie state.)*
- Site never depends on GT for any core function.

### Testing

- **Unit (jest):** language-map completeness (every code valid ISO-639-1, grouped correctly), button render, cookie-set helper logic.
- **E2E (Playwright):**
  - `translate.*` requests route-mocked hermetically (Ko-fi precedent) so the axe suite stays deterministic.
  - New test: button visible below theme toggle, matching size; menu opens/closes; selecting a language writes the expected `googtrans` cookie value.
  - axe scans unaffected by hidden GT containers (mock keeps DOM inert).

### Config

- **netlify.toml CSP** must add: `translate.google.com` (script-src), `translate.googleapis.com` + `translate-pa.googleapis.com` (connect-src). Explicitly user-approved. Without it the feature fails in production only.
- `sw.js`: no precache changes (GT is runtime-only); bump `CACHE_NAME` when `language-toggle.js` ships.

## Phase 2 — Swedish Quality Overlays (future spec)

Sketched here so Phase 1 doesn't paint us into a corner; detailed design comes later:

- EN shards remain canonical; Swedish lives as slug-keyed field overlays in `data/i18n/sv/{creatures,stories,items}-{region}.json`.
- One merge point inside Shimmer decorates entries → viewers, search, quiz, daily-feature get sv automatically.
- Per-entry fallback to English with a visible machine-translation-pending marker (project rule: mark uncertain data clearly).
- `?lang=sv` URLs, `<html lang>` switching, hreflang alternates, localized meta.
- Toggle prefers overlay content for sv when available; falls back to GT for other languages.

Phase 1 constraints that keep Phase 2 possible: all GT wiring isolated in one module; no URL semantics claimed; language list data kept in one importable map.

## Out of scope

- Server-side translation, build step, duplicated page files
- Translating quiz answer-shuffling logic behavior
- Right-to-left layout audit beyond basic rendering (no RTL language ships in the initial whitelist unless trivially supported by GT)
